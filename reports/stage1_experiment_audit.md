# 第一阶段：原实验、指标与学习接入审计

审计日期：2026-10-21。范围为修改前代码、既有 CSV/JSON 和轻量 MuJoCo 诊断；本报告不训练或修改学习算法。下列源码行号指**本次修复前的版本**，修复后请同时按函数名定位。既有结果文件保留，不作为修复后结果。

## 结论

用户提出的六项异常均有可定位问题。原实验确实运行 MuJoCo 两刚体及八电机，但仅观察沿 Y 接近运动中很小的 pitch 分量；接触和 weld 力没有原始持久化记录；实验中跨试验状态未重置、失败样本被删除；恢复时间的初始值错误；ECLR 的训练/推理特征含义不一致。已有材料不能证明 ECLR 优于固定前馈，更不能代替物理模型验收。

| 异常 | 直接证据 | 判断 |
|---|---|---|
| pitch 峰值约 0.001° | `evaluate_splits.py:41–55` 仅取 CONNECTED 后 Q1 pitch；`sim_runner.py:150–175` 只沿 Y 接近 | 测量轴和事件窗口遗漏主要 roll、接触前段及分离，不能把小 pitch 等同于无瞬态 |
| Fixed FF 均值更低 | 既有 CSV，见下表；同配对样本仍存在 Fixed FF 更优的结果 | 必须保留负结果；当前有特征错位、控制方向错位及不配对干扰，无法归因算法优劣 |
| 15 工况只有 33 行 | `run_experiments.py:85–102` 仅在 `success` 时写入 | 60 次预期尝试仅保留 33 次，27 次缺失且无失败原因 |
| 全部 settling=1.2 | `evaluate_splits.py:57–62` 初始设 1.2，只在出现越界时更新 | 全程在容差内的正确值应为 0，旧实现恰好保留 1.2；末点越界也未标截尾 |
| 接触/约束物理无法核查 | 旧日志 `sim_runner.py:255–276` 不保存接触力、约束力、动量或能量 | 不能从原 CSV 反推物理；轻量运行可见非零接触，仍有固定参考 weld 误差 |
| 简化模型与 MuJoCo 不一致 | surrogate 直接向角加速度加补偿；MuJoCo 通过电机，但用错特征且主要作用 roll | 两种模型的输入、扰动和评价量不同，不应把 surrogate 的改善当作 MuJoCo 效果 |

## 指标错误的具体路径

`evaluate_trial` 在缺少 CONNECTED 时返回 `{'success': False}`（`evaluate_splits.py:42–44`），有 CONNECTED 就视为成功，未要求释放完成、观察窗口完整、状态有限或飞行稳定。旧文件中 trial 0 的 fixed_ff 与 ilc 的 peak 恰好等于 RMS，提示窗口可能极短；原文件没有窗口长度，不能据此确认完整 1.2 s 观察。

恢复时间代码等价于：

```python
settling_time = 1.2
for i in reverse_indices:
    if abs(pitch[i]) > 0.5:
        settling_time = time[min(i + 1, last_index)]
        break
```

33 条记录的最大 pitch 峰值只有 **0.0020235058370658295°**，全部远小于 0.5°。因此反向循环永远不进入条件，输出初始值 1.2。按用户定义，对于这些**已记录 pitch 窗口**正确恢复时间均为 0；窗口是否完整、roll/position 是否恢复则无法由该 CSV 判定。若最后一个采样点仍越界，该算法仍给出有限数，错误地把未恢复计为恢复。

其他缺项：没有参考姿态误差而直接取绝对 pitch；没有 roll、两机整体位置误差、积分误差、输入能量、变化率、饱和率、实际事件成功率及截尾统计；没有单元测试覆盖指标边界。

## 学习器实际接入链路与不一致

真实链路存在：`collect_eclr_dataset` 读取 `runner.run_scenario()` 的 MuJoCo 日志（`fit_eclr.py:46–95`），岭回归得到 A/G（100–112）；`evaluate_trial` 把 A/G 传入 C++（`evaluate_splits.py:26–30`）；FSM 进入 CONNECTED 时 `trigger_event`（`sim_runner.py:116–128`）；`evaluate(t,8)` 返回电机增量并叠加名义分配（229–232）；随后整体幅值裁剪（252–253）；`MuJoCoWorld.step` 经过一阶电机响应写入 `data.ctrl` 再 `mj_step`（`mujoco_world.py:91–103`）。所以问题不是“学习量只写日志、完全没进电机”。

但该链路有以下确定的不一致：

1. **训练/推理特征错位。** 训练的 4 列是 `[approach_offset, q1_init_y+0.6, q2_init_y-0.6, 1]`（`fit_eclr.py:84–93`）；推理传 13 列相对位置、速度、占位角度、相对角速度及单电机差（`sim_runner.py:120–128`）。`compensator.cpp:58–60` 静默取 A 列数和特征长度的较小值，所以实际用 `[rel_x,rel_y,rel_z,rel_vx]` 解释成训练的前三个条件及 bias。bias 丢失，初始条件与事件状态也非同一种量。
2. **主要控制方向与目标不符。** 连接后补偿为前四电机 `+scalar/2`、后四 `-scalar/2`（`compensator.cpp:163–168`）；双机沿 Y 排布，因此力臂产生 Mx（roll），对称布局下 My（pitch）为零。训练 Y 却仅为 Q1 pitch（度）及 pitch rate（rad/s），还未按物理尺度加权（`fit_eclr.py:76–82`）。注释“pitch torque”与几何不一致。
3. **分离模型没有独立辨识。** 主程序仅 `collect_eclr_dataset(..., mode='dock')`（`run_experiments.py:56`）。DOCK/UNDOCK 用同一 A/G；C++ 只存事件名，不按事件选择模型（`compensator.cpp:110–129`）。分离输入为 9 维且同样会被截断。
4. **没有逐轮 ECLR 更新。** A/G 训练一次，随后冻结测试；不保存模型拟合残差、训练/验证划分清单或学习曲线。不能据此声称已演示迭代学习改进。
5. **ILC 输出采样不匹配。** G 的前 15 行对应整个 1.2 s 内均匀采样 pitch（`fit_eclr.py:76–82`）；ILC 更新却取日志前 15 个连续控制采样（`run_experiments.py:71–73`），原控制频率下跨度约 56 ms。其时间基准不一致。
6. **限幅/变化率实施位置不完整。** 名义分配器先做 slew，再加补偿，最终仅 clip 幅值；新增补偿没有最终共同 slew 约束（`sim_runner.py:226–253`）。事件补偿不受与基线相同的完整输入链约束。

轻量 C++ 补偿器诊断（未改模型、未训练）：四个固定系数均为 0.2，在事件后 0.1 s 返回前四电机 `+0.11204940830547772 N`、后四 `-0.11204940830547772 N`。用 XML 旋翼位置构造 B，得到 `[Fz,Mx,My,Mz]=[0,-0.19720695861764076,0,0]`。另取 A 的 bias 列全 1、G=I，实际 13 维零状态得到全零系数；正确 `[0,0,0,1]` 得到四个 `-0.9999000099990001`，直接复现特征/bias 错位。

## 轻量 MuJoCo 原实现复现

运行参数：新建 `SimulationRunner()`，`duration=6.5`、`dock_cmd_time=1.0`、`undock_cmd_time=4.5`，默认初值、无学习。包装 `world.step` 只读采集每个物理步的 `data.ncon`、`LatchManager.check_contacts()` 与 `norm(data.qfrc_constraint)`，不添加外力、不修改姿态。

| 控制日志间隔 | 0.004 s（实际 250 Hz） |
| CAPTURE_PENDING 首时刻 | 3.119999999999878 s |
| CONNECTED 首时刻 | 3.147999999999875 s |
| 激活时连接点位置误差范数 | 0.011311962463880623 m |

这里 `qfrc_constraint` 同时含接触和 equality，不能把该范数叫做 weld 力。以上足以否定“完全没有发生任何接触”的假定，但不能替代单独的接触冲量、weld 行力和动量平衡测试。分离 roll 中还含参考轨迹所需倾斜，不能直接把绝对 roll 全部解释成冲击误差。

关键物理/控制证据：

- 两个真实 `freejoint`、独立质量惯量、八个 site motor 均存在（`dual_quads.xml:25–27,55–57,85–104`），默认 SI 单位；不存在事件时直接设置姿态的代码。初始状态设置与运行中的 teleport 应区分。
- 固定 `relpose="0 0.44 0 1 0 0 0"`（XML:104），`engage_weld` 仅激活，不更新参考（`latch_manager.py:36–40`、`mujoco_world.py:63–65`）。默认复现已在约 11.3 mm 接口误差时开启，因而“按当前相对位姿激活、彻底无虚假冲量”的文档说法未经实现支持。
- FSM 捕获只看距离、速度、姿态与 dwell（`core/src/fsm.cpp:61–66,120–129`），不读取接触确认。`check_contacts` 原先未被主循环调用。接口 site 在 ±0.22 m，但两圆柱中心在 ±0.20 m，默认圆柱轴沿 Z（XML:49–51,79–81），需核对真实接触位置与捕获基准。
- `round(0.005/0.002)` 取 2，原主循环每 4 ms 控制一次，却向 C++ 传 5 ms（`sim_runner.py:25–26,88–99`）。dwell、模式过渡、积分和分配 slew 使用的时间基准均受影响；原 100 ms 释放准备实际为约 80 ms。
- 原释放仅关闭 weld，没有瞬时写速度（`latch_manager.py:42–46`）；但旧“连续性”测试仅比较相邻日志 Q1 pitch rate、容差 0.5 rad/s（`tests/test_docking_latch.py:34–54`），并非在零外力零预载下核对全部线/角速度。不能证明完整物理连续性。
- 非零 preload 分支只向 `qfrc_applied` 加力，没有储能状态、加载历程或清零（`latch_manager.py:48–56`）；不是已验证的短时释放机构模型。

## 跨试验状态污染的直接复现

`run_scenario` 仅重置 world、FSM、compensator（`sim_runner.py:82–86`），没有重置三套控制器、三套分配器及 setpoint。分配器 `prev_thrusts_`、积分器及上一轮 `Setpoint.acc` 会保留；FREE 分支只写 pos/vel（144–148），未把 acc 复零。整个 full matrix 又复用同一个 runner（`run_experiments.py:51,85–89`），因此方法执行顺序改变后续方法初态。

复现顺序：先运行上述 nominal baseline；用 `sample_pre_event_conditions(2, seed=1042, test=True)` 依次生成两条件。每个条件比较复用 runner 和新建 runner，配置均无学习、同样运行 6.5 s。

| 条件 | 复用 runner 的 CONNECTED 日志数 | 新 runner 的 CONNECTED 日志数 | 首步平均电机输入（Q1,Q2）复用 / 新建 |
|---|---:|---:|---|
| 0 | 76 | 357 | (2.45224167880984,2.4522412099405213) / (2.4516625,2.4516625) |
| 1 | **0** | **68** | (2.45239058152528,2.4523853465082603) / (2.4516625,2.4516625) |

这证明相同物理初始位置和方法标签不足以构成相同实验初态；跨试验内部状态能够改变捕获是否成功。不能从旧 CSV 指认某一次失败的唯一原因，因为失败日志被丢弃。

## surrogate 与文档声明的边界

`src/event_surrogate.py:46–88` 是二维线性闭环角度/角速度模型，以手工指数扰动和角加速度补偿驱动，不含双机刚体、接触、weld、电机或组合控制。dock/undock 的扰动初值、幅值均由 feature 的人工公式决定；其设计本身就提供明显可学习相关性。`README_CN.md:9–21` 正确标注其用途，相关图表应持续保留 synthetic 标识。

`README.md:101–105` 声称严格约束分配、当前位姿 weld、无虚假冲量及已验证零预载连续性，超过原实现/测试证据。`requirements.txt` 原只列 numpy/matplotlib/pytest，未列实际导入的 mujoco、pybind11 和 YAML 依赖；原 YAML 参数也未由主循环载入，文档配置与实际默认值可能不同。应在第二阶段按实际运行链统一参数和说明。
